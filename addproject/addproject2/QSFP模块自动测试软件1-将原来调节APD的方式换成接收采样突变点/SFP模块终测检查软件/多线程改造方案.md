# QSFP光模块测试软件 - 多线程改造方案

## 一、现状分析

### 1.1 当前架构（单线程串行）
```
Main_Form（主窗口）
  ├─ GlobalVarFun（全局静态变量库）← 所有共享状态都在这里
  ├─ TestSet（当前测试参数）← 全局唯一，包含 ch（当前通道）
  ├─ TestResult（当前测试结果）← 全局唯一
  ├─ test: ModuleTest（模块I2C操作对象）← 全局唯一
  ├─ opticalSwitch（光开关串口）← 全局唯一，4个模块共享
  ├─ kt86120c（波长计）← 全局唯一
  └─ heater（加热台）← 全局唯一，支持4个槽位(slot 1-4)
```

## 二、改造目标

**同时测试4个光模块**，每个模块在一个独立的线程中运行完整的测试流程。

## 三、改造方案

### 3.1 核心思路：每模块独立的"测试上下文"

当前代码的问题：`TestSet.ch`、`TestResult`、`test`（ModuleTest对象）都是全局唯一的。
多线程时，4个线程会互相覆盖这些变量，导致数据混乱。

**解决方案**：为每个模块创建一个独立的"测试上下文"（TestContext），包含：
- 独立的 `TestSet`（测试参数副本）
- 独立的 `TestResult`（测试结果）
- 独立的 `test`（ModuleTest对象，绑定独立的I2C）
- 模块槽位号 `slot`（1-4）

### 3.2 共享资源的线程同步

对于光开关、波长计、示波器等全局唯一的设备，使用 `lock` 排队访问：

```csharp
private static readonly object _opticalSwitchLock = new object();

private bool OpticalSwitchSetThreadSafe(int ch)
{
    lock (_opticalSwitchLock)
    {
        return opticalSwitchSet(ch);
    }
}
```

### 3.3 改造步骤

1. **创建 TestContext 类** — 封装每个模块的独立测试状态
2. **创建 ThreadManager 类** — 管理4个测试线程的启动/等待/状态
3. **修改 FirstTestProcess / FinalTestProcess** — 接收 TestContext 参数
4. **修改8处4通道循环** — 改为操作 TestContext 中的独立状态
5. **修改 opticalSwitchSet** — 加线程锁
6. **修改 UI 更新** — 使用 Invoke 安全更新控件
7. **修改 Main_Form** — 添加4路并行启动逻辑
